# MyStyle AI

AI хувийн стилист — хэрэглэгчийн биеийн онцлог, нүүрний хэлбэр, арьсны өнгөнд тулгуурлан
хувцас, өнгө, үсний засалтын зөвлөгөө гаргадаг веб апп.

## Юу багтсан бэ

- Стилийн тест (quiz)
- Selfie зураг оруулах боломж (AI зургаас нүүрний хэлбэр уншина)
- AI-аар үүсгэсэн хувийн тайлан: тохирох хэлбэр, өнгөний palette, үсний засалт, outfit санаа
- Улаанбаатарын улирлаар өнөөдрийн хувцасны санал
- Өнгө бүрийн гүнзгий тайлбар: яагаад тохирох, яаж харагдуулах, ямар сэтгэгдэл төрүүлэх
- Размер & загвар: үсгэн/тоон размер, солонгос/хятад брэндийн зөвлөгөө, тохирох fit (сул/дунд/нарийн)
- **Шүүгээний зураг (20 хүртэл)** — хувцас бүрийг тохирох түвшнээр (маш сайн / сайн / дунд / бага) үнэлж шалтгааныг хэлнэ, зөвхөн тэдгээр хувцаснаас 7 хоногийн өдөр бүрийн хослол гаргана
- **Дэлгүүрт туршиж буй зургийн хурдан шалгалт** (`/api/tryon`) — нэг зургаар тохирох эсэх, яагаад, юуг өөрчлөх; өмнө бөглөсөн биеийн хэлбэр, өнгөлөг, стиль, өмнөх тайлангийн palette-ийг ашиглана. Зураг ч, хариу ч хадгалагдахгүй
- Биеийн хэмжээ (цээж, бэлхүүс, ташаа) — заавал биш, размерийг нарийвчилна
- Нэвтэрсэн хэрэглэгчид тест өмнөх хариултаар урьдчилан бөглөгдөнө
- PDF татах
- Premium түгжээ (худалдан авалтын зөвлөмж) — мөнгө төлөх сонирхлыг шалгах хэсэг
- **Бүртгэл / нэвтрэлт** (и-мэйл + нууц үг) ба **тайлан хадгалах** («Миний тайлангууд»)
- Нэвтрээгүй гаргасан тайлан бүртгүүлэхэд автоматаар хадгалагдана
- **API зардлын хяналт** — үнэгүй хязгаар, IP хязгаар, өдрийн нийт cap, ижил хариултын cache
- **Хэрэглээний статистик** — `/api/admin/stats` (хэрэглэгч, тайлан, дахин ирсэн хэрэглэгч, token, $ зардал)
- Нууцлалын бодлого (`/privacy.html`), бүртгэл + тайлангаа устгах боломж

## 1. Юу хэрэгтэй вэ

- **Node.js 20.6 ба түүнээс дээш** (`node -v` гэж шалгана)
- **Anthropic API key** — https://console.anthropic.com → API Keys.
  Анхаар: API дуудалт бүр мөнгөтэй. Эхэндээ бага лимит/budget тавь.

## 2. Локал дээр ажиллуулах

```bash
# 1. Хамаарал суулгах
npm install

# 2. .env үүсгэх
cp .env.example .env
# дараа нь .env-г нээж ANTHROPIC_API_KEY=... -ээ бөглө

# 3. Ажиллуулах
npm start
```

Дараа нь browser дээр http://localhost:3000 нээ.

Локал дээр `DATABASE_URL` хоосон бол өгөгдөл `data/db.json` файлд хадгалагдана.

Тест: `npm test` (Claude-г mock хийдэг тул API key, мөнгө шаардахгүй).

## 3. Интернэтэд гаргах (deploy)

Production дээр дараах environment variable-ууд **заавал**:

| Хувьсагч | Юу вэ |
|---|---|
| `ANTHROPIC_API_KEY` | Claude API key |
| `DATABASE_URL` | Postgres connection string. [Neon](https://neon.tech) эсвэл Supabase-ийн үнэгүй tier хангалттай. Хүснэгтүүд анхны хүсэлтээр автоматаар үүснэ. |
| `SESSION_SECRET` | Санамсаргүй урт нууц (`openssl rand -hex 32`) |
| `ADMIN_TOKEN` | Статистик харах нууц |

Хязгаарын тохиргоо `.env.example` дотор тайлбартай байгаа.

Neon дээр **Pooled connection** string ашигла (host дотор `-pooler`) — serverless-д холболт хэтрэхээс сэргийлнэ.

`vercel.json` функцийн хугацааг 60 секунд (`maxDuration`), `public/` файлуудыг багцад (`includeFiles`) оруулна.
Vercel дээр `CLAUDE_TIMEOUT_MS=55000` тавь — функц таслагдахаас өмнө Claude хүлээлт зогсож, хэрэглэгчид ойлгомжтой алдаа харагдаж, эрх нь буцна.

Deploy хийсний дараа шалгах:
```bash
node scripts/smoke.js https://<домэйн>            # хуудас, PWA, DB холболт
node scripts/smoke.js https://<домэйн> --write    # + түр хэрэглэгч бүртгээд устгана
node scripts/smoke.js https://<домэйн> --report   # + бодит Claude тайлан (1 удаа, ~$0.05–0.10)
```
Preview хамгаалалттай бол `VERCEL_BYPASS=<token>` өгнө.

Хамгийн хялбар хувилбарууд (бүгд үнэгүй tier-тэй):

### Render.com
1. Кодоо GitHub-д push хий (`.env`-г **бүү** push хий — `.gitignore` дотор байгаа).
2. Render дээр New → Web Service → GitHub repo-гоо сонго.
3. Build command: `npm install` · Start command: `npm start`
4. Environment → `ANTHROPIC_API_KEY`-ээ нэм.

### Railway.app эсвэл Fly.io — мөн адил: repo холбоод env variable нэмнэ.

> **Чухал:** API key-г зөвхөн серверийн environment variable-д тавина.
> Frontend код (index.html) дотор хэзээ ч бүү тавь — нийтэд ил болж, мөнгийг чинь зарцуулна.

## 4. Загвар (model) сонгох

`.env` дотор `MYSTYLE_MODEL`-оор удирдана ($ / 1M token, input / output):
- `claude-sonnet-4-6` — default. Бодит модель (Claude Sonnet 4.6), $3 / $15
- `claude-sonnet-5-5` — шинэ үеийн Sonnet, $2 / $10
- `claude-haiku-5-5` — хамгийн хямд, $0.10 / $0.50 — чанарыг туршиж үзээд сонго

## 5. Зардлын хяналт хэрхэн ажилладаг вэ

`/api/style` хүсэлт бүр Claude дуудахаас **өмнө** доорх тоолууруудыг DB-д шалгана:

| Хязгаар | Default | Env |
|---|---|---|
| Нэвтрээгүй, IP тутамд өдөрт | 1 | `FREE_ANON_PER_DAY` |
| Бүртгэлтэй хэрэглэгч, сард | 5 | `FREE_USER_PER_MONTH` |
| Нэг IP-аас өдөрт (олон account) | 10 | `IP_PER_DAY` |
| Бүх хэрэглэгч нийлээд өдөрт | 300 | `GLOBAL_PER_DAY` |
| Нэвтрэх оролдлого, IP тутамд цагт | 20 | `AUTH_PER_HOUR` |

`/api/tryon` (дэлгүүрт туршиж буй зураг) тайлангаас **тусдаа** тоологдоно — нэг зураг, ~1500 token-оос бага хариу тул тайлангаас хэд дахин хямд:

| Хязгаар | Default | Env |
|---|---|---|
| Нэвтрээгүй, IP тутамд өдөрт | 3 | `TRYON_ANON_PER_DAY` |
| Бүртгэлтэй хэрэглэгч, өдөрт | 20 | `TRYON_USER_PER_DAY` |
| Нэг IP-аас өдөрт | 40 | `TRYON_IP_PER_DAY` |
| Бүх хэрэглэгч нийлээд өдөрт | 1000 | `TRYON_GLOBAL_PER_DAY` |

Try-on-ий token хэрэглээ `events` хүснэгтэд (`name='tryon'`, `meta`) бичигдэнэ. `/api/admin/stats`-ийн $ зардалд одоогоор ороогүй.

- Хязгаар хэтэрвэл `429` буцааж, Claude дуудахгүй. AI алдаа гарвал хасагдсан эрх буцаж өгөгдөнө.
- Зураггүй, яг ижил хариулттай хүсэлтэд өмнөх тайланг cache-аас өгнө (Claude дуудахгүй, эрх хасахгүй).
- Өдрийг Улаанбаатарын цагаар (UTC+8) тоолно.
- Нэмэлт хамгаалалт: Anthropic Console дээр сарын spend limit заавал тавь.

## 6. Олон дэлгүүр (multi-tenant) ба админ

**Роль:**

| Роль | Юу хийж чадах вэ |
|---|---|
| `SUPER_ADMIN` | Дэлгүүр нэмэх, зогсоох, өдрийн хязгаар тавих, аль ч дэлгүүрт OWNER/MANAGER оноох, бүх статистик + Claude зардал |
| Дэлгүүрийн **OWNER** | MANAGER-ийн бүх эрх + өөрийн дэлгүүрт админ нэмэх, хасах, түвшин солих |
| Дэлгүүрийн **MANAGER** | Өөрийн дэлгүүрийн нийлбэр статистик, нэр/брэнд өнгө засах |
| `USER` | Энгийн хэрэглэгч |

- Нэг хүн хэд хэдэн дэлгүүрийн OWNER/MANAGER байж болно — админ хуудсанд бүх дэлгүүр нь харагдаж, статистикийг нийлбэрээр эсвэл дэлгүүр тус бүрээр харна.
- Дэлгүүрт **дор хаяж нэг OWNER** байх ёстой: сүүлийн OWNER-ийг хасах эсвэл MANAGER болгохыг (SUPER_ADMIN ч) хориглоно.
- Дэлгүүрийн админ хэрэглэгчийн хувийн тайлан **харахгүй**. Хэрэглэгчийн (end user) тал өөрчлөгдөхгүй.
- Холбоос `store_admins(store_id, user_id, level)` хүснэгтэд хадгалагдана. `users.role` нь зөвхөн `SUPER_ADMIN`/`USER`; API-ийн `STORE_ADMIN` роль нь «дор хаяж нэг дэлгүүрийн админ» гэсэн тооцоолсон утга.

**Эхлүүлэх:**
1. `.env`-д `SUPER_ADMIN_EMAILS=таны@имэйл.mn` тавиад тэр и-мэйлээр апп дээр бүртгүүлэх/нэвтрэх → SUPER_ADMIN болно.
2. `/admin.html` → дэлгүүр нэмэх (нэр, slug, брэнд өнгө, өдрийн хязгаар).
3. Дэлгүүрийн эзэн апп дээр бүртгүүлсний дараа түүнийг «+ Админ»-аар **OWNER** болгох. Цаашид тэр өөрөө ажилтнуудаа MANAGER болгон нэмнэ.
4. Хэрэглэгчдэд `https://<домэйн>/s/<slug>` холбоос өгнө (QR болгож дэлгүүрт байрлуулж болно).
   Тэр хуудас дэлгүүрийн нэр, өнгөөр харагдаж, гарсан тайлан бүр `store_id`-тай хадгалагдана.

Хэрэглэгчийн бүртгэл нэг л байна — нэг хүн хэд хэдэн дэлгүүрээр орж болно. Тайлангийн хязгаар (`FREE_*`) хэрэглэгч бүрд нийтээрээ, дэлгүүрийн `daily_cap` нэмэлтээр үйлчилнэ.
DB хүснэгтүүд (`stores`, `store_admins`, `role`, `store_id` баганууд) анхны хүсэлтээр автоматаар нэмэгдэнэ — хуучин өгөгдөл хэвээр үлдэнэ.
`store_admins` анх үүсэхэд хуучин `STORE_ADMIN` + `users.store_id` бүхий хэрэглэгчид **нэг удаа** OWNER болж хуулагдана. `users.store_id` баганыг rollback-д зориулж үлдээсэн (шинэ код ашигладаггүй) — дараагийн хувилбарт устгана.

## 7. PWA (апп шиг суулгах)

- `manifest.json` (`id`, `start_url`, `scope`, `display: standalone`, theme/background өнгө, icon 192/512/maskable, Android-ийн суулгах цонхны `screenshots/`), `sw.js`, `apple-touch-icon.png`
- «📲 Апп татах»: нүүр хуудасны блок + дээд мөрийн товч. Browser тус бүрд:
  - Chrome / Edge / Samsung Internet (Android, desktop) — `beforeinstallprompt`-ийг барьж өөрийн товчоор системийн суулгах цонхыг гаргана
  - iPhone/iPad (бүх browser) — «Хуваалцах → Нүүр дэлгэцэд нэмэх» 3 алхмын заавар
  - Facebook / Instagram доторх browser — суулгах боломжгүй тул «Safari/Browser-т нээх» заавар
  - Суулгасны дараа «✓ Суулгасан»; апп дотроос (standalone) нээгдсэн үед товч харагдахгүй
- Шалгах: Chrome DevTools → Application → Manifest («Installability» алдаагүй байх). Lighthouse 12-оос PWA ангилал хасагдсан.
- Өөрчлөлтийн дараа `sw.js`-ийн `VERSION`-ийг нэмэгдүүлбэл хуучин cache цэвэрлэгдэнэ.
- Дэлгүүрийн хуудаснаас суулгавал апп тухайн дэлгүүрийн нэрээр, тухайн хуудсаараа нээгдэнэ (`/s/<slug>/manifest.json`)
- Service worker зөвхөн хуудас, icon-уудыг cache хийнэ. `/api/*` (тайлан, хувийн мэдээлэл, зураг) **хэзээ ч cache хийгдэхгүй**
- PWA зөвхөн HTTPS дээр ажиллана (Vercel автоматаар HTTPS). Локалд `localhost` дээр ажиллана.

## 9. Статистик

```bash
curl -H "Authorization: Bearer $ADMIN_TOKEN" https://<домэйн>/api/admin/stats
```

Хэрэглэгчийн тоо, нийт/өнөөдрийн/7 хоногийн тайлан, cache-ийн тоо, **2+ тайлан гаргасан (дахин ирсэн) хэрэглэгч**,
token хэрэглээ, $ зардлын тооцоо, товч дарсан тоо (`premium_click`, `pdf_click`, `signup` гэх мэт).

## Дараагийн алхмууд (validate хийсний дараа)

1. **Жинхэнэ төлбөр** — QPay / Storepay / SocialPay холболт, Pro хэрэглэгчид хязгаарыг нэмэх.
2. **Нууц үг сэргээх, и-мэйл баталгаажуулах** — одоогоор байхгүй.
3. **PDF** — одоо `window.print()`. Жинхэнэ PDF (сервер дээр үүсгэх) хийх.
4. **Зураг хадгалалт** — одоогоор selfie, хувцасны зургийг хадгалдаггүй (privacy-д сайн).
   Хадгалсан тайланд шүүгээний зураг харагдахгүй, зөвхөн текст. Хадгалах бол зөвшөөрөл аваад аюулгүй storage ашигла.
5. **Нэвтрээгүй хуучин тайлан цэвэрлэх** — claim хийгдээгүй тайланг 30 хоногийн дараа устгах cron.
